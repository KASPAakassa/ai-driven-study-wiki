# 端到端机器学习项目实战:从任务定义到结论的完整流程

> **一句话摘要**:用一次真实的房价预测项目(纯 Python + numpy,零外部 ML 库),把「问题定义 → EDA → 标准化 → 训练 → 评估 → 结论」完整走一遍,并给出项目目录结构与复盘清单。
>
> **来源**:综合公开资料(Andrew Ng ML Course、Kaggle 房价竞赛),代码为本项目自研验证。

## 概念

- **端到端(End-to-End)流程**:机器学习不是"写个模型训练一下"这么简单,而是一条完整流水线——**问题定义 → 数据准备 → 特征工程 → 建模 → 评估 → 部署 → 复盘**。每一环的错误都会向下游放大。
- **为什么要学完整流程**:80% 的实战时间花在数据与评估上,而不是模型代码上。会跑 `model.fit()` 不等于会做机器学习项目。
- **教科书 vs 实战的差异**:教科书给你一个"洗好的数据集 + 明确目标";实战里数据要自己造/清洗、目标要和业务对齐、评估要选对指标。

## 原理

### 标准流程七步

| 步骤 | 要回答的问题 | 常见产出 |
|---|---|---|
| 1. 问题定义 | 预测什么?回归还是分类?成功标准是什么? | 目标指标(如 RMSE) |
| 2. 数据获取与探索(EDA) | 数据长什么样?特征与目标相关吗? | 统计量、相关系数、可视化 |
| 3. 数据预处理 | 缺失值、异常值、量纲 | 清洗后的数据集 |
| 4. 特征工程与划分 | 特征如何构造?如何避免泄漏? | 训练/验证/测试集 |
| 5. 建模与训练 | 用什么模型?怎么调参? | 训练好的模型 |
| 6. 评估与诊断 | 泛化能力如何?过拟合吗? | 指标报告、诊断图 |
| 7. 结论与复盘 | 结论可解释吗?哪里能改进? | 总结报告 |

### 三个贯穿全局的关键决策

- **数据划分必须"先切后处理"**:标准化、缺失值填充等统计量**只能在训练集上计算**,再应用到验证/测试集。在全部数据上算均值再划分 = 把测试集信息泄漏进训练(见[排查清单](practice-debug-checklist.md)的数据泄漏)。
- **回归用 RMSE/R²,分类用准确率/混淆矩阵**:指标要和业务目标绑定——房价预测报"平均误差 14 万"比报"准确率 90%"更有意义。
- **基线先行**:先跑最简单的线性模型作为基线,再决定要不要上复杂模型。基线能帮你判断复杂模型的收益是否值得。

## 代码 / 实现

> 环境:`python3` + `numpy`(本项目不依赖 sklearn 等 ML 库)。完整脚本可直接保存为 `train.py` 运行。

```python
import numpy as np

# ---------- 1. 问题定义:预测房价(回归) ----------
# 输入:面积 area、房间数 rooms、楼龄 age;输出:价格 price(万元)
rng = np.random.default_rng(42)
n = 300
area = rng.uniform(40, 200, n)                      # 40~200 ㎡
rooms = rng.integers(1, 6, n).astype(float)         # 1~5 间
age = rng.uniform(0, 40, n)                         # 0~40 年
# 真实生成规则(噪声=15 万),即我们要"学"的东西
price = 60 + 2.2 * area + 8 * rooms - 1.8 * age + rng.normal(0, 15, n)
X = np.column_stack([area, rooms, age])
y = price

# ---------- 2. EDA:统计量 + 相关性 ----------
print("形状:", X.shape, " 特征均值:", X.mean(axis=0).round(2))
corr = np.corrcoef(X.T, y)[:-1, -1]
print("特征与价格相关系数:", corr.round(3))
# 预期输出: 面积 ~0.96(强正相关)、房间数 ~0.1(弱)、楼龄 ~-0.27(负相关)

# ---------- 3. 划分数据 + 标准化(只在训练集上 fit!) ----------
def zscore(X):
    mean, std = X.mean(axis=0), X.std(axis=0)
    return (X - mean) / std, mean, std

idx = rng.permutation(n)                            # 打乱
tr, te = idx[:240], idx[240:]                       # 8:2 划分
Xs, mean, std = zscore(X[tr])                       # fit 训练集
Xte = (X[te] - mean) / std                          # 用训练集的参数 transform
ytr, yte = y[tr], y[te]

# ---------- 4. 训练:批量梯度下降 + L2 正则(复用线性模型章节知识) ----------
def train(X, y, lr=0.1, epochs=2000, lam=0.01):
    m, d = X.shape
    w = np.zeros(d); b = 0.0
    for _ in range(epochs):
        pred = X @ w + b
        grad_w = X.T @ (pred - y) / m + lam * w     # + L2 正则防过拟合
        grad_b = (pred - y).mean()
        w -= lr * grad_w; b -= lr * grad_b
    return w, b

w, b = train(Xs, ytr)
pred = Xte @ w + b

# ---------- 5. 评估:RMSE + R² ----------
rmse = np.sqrt(np.mean((pred - yte) ** 2))
ss_res = np.sum((yte - pred) ** 2)
ss_tot = np.sum((yte - yte.mean()) ** 2)
r2 = 1 - ss_res / ss_tot
print(f"RMSE = {rmse:.2f} 万元, R² = {r2:.3f}")
print("权重(标准化尺度):", w.round(3), " 截距:", round(b, 3))
# 预期输出: RMSE ≈ 13~14 万元, R² ≈ 0.98;权重正负方向符合业务直觉
```

**逐段解释**:

- **第 1 步**把"业务问题"翻译成"数学问题":`ŷ = w1·area + w2·rooms + w3·age + b`,成功标准 = RMSE 越小越好。注意我们给数据加噪声(±15 万),模拟真实世界的不完美。
- **第 2 步 EDA** 用相关系数 `np.corrcoef` 快速判断特征与目标的关系强度,提前发现"哪些特征可能是主要驱动"。
- **第 3 步**是最容易犯错的环节:**标准化参数只能从训练集学**。如果对整个数据集算 mean/std,测试信息就泄漏了。
- **第 4 步**复用[线性回归章节](../01-ai-basics/ml-linear-models.md)的梯度下降:`grad_w = Xᵀ(pred-y)/m + λ·w`,其中 `λ·w` 是 L2 正则。
- **第 5 步**回归用 RMSE(与 y 同量纲,可业务解释)和 R²(解释了多少方差)。

## 实践 / 应用

### 建议的项目目录结构

```text
housing-price/
├── README.md          # 项目目标、指标、结论
├── data/
│   ├── raw/           # 原始数据(只读,不修改)
│   └── processed/     # 清洗、特征工程后的数据
├── src/
│   ├── preprocess.py  # 清洗 + 标准化(统一入口)
│   ├── train.py       # 模型训练
│   └── evaluate.py    # 评估与图表
├── notebooks/         # EDA 探索(可放 .py 或 jupyter)
└── results/           # 指标、图表、模型文件
```

### 复盘清单(每个项目做完过一遍)

- [ ] 问题定义是否清晰:目标变量、回归/分类、成功指标是否确定?
- [ ] 划分是否在预处理**之前**完成?测试集是否从未参与任何 fit?
- [ ] 特征是否标准化?是否处理了缺失值/异常值?
- [ ] 是否先跑了**基线模型**再上复杂模型?
- [ ] 评估指标是否和业务目标对齐?是否同时看了训练/验证两个指标?
- [ ] 结论是否回到业务语言(如"平均误差 14 万,面积每 +10㎡ 价格约 +22 万")?

### 常见坑

- 忘记标准化 → 梯度下降震荡不收敛(线性模型尤其敏感);
- 用全量数据计算预处理统计量 → 数据泄漏,验证指标虚高;
- 只看训练集指标 → 把过拟合当成功;
- 未固定随机种子 → 结果不可复现,调参无从谈起。

## 总结

- 端到端流程 = 问题定义 → EDA → 预处理 → 建模 → 评估 → 复盘,每步都要有产出物。
- 核心纪律:**先切分、后预处理**;基线先行;指标与业务绑定。
- 回归评估用 RMSE + R²,并同时监控训练/测试差距诊断过拟合。
- 一个完整的 300 行以内项目(含预处理),比十段孤立代码更能建立全局观。
