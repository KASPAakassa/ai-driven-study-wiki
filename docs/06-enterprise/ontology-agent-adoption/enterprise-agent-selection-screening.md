# Agent 落地失败的根因在筛选:三个筛子选对活儿

> **一句话摘要**:跟进了 40 多家 50-200 人公司的 Agent 项目后,一个产品经理得出判断——**落地失败的原因九成不在技术,在"筛选"**:筛错了岗位、筛错了任务、筛错了组织土壤。本文拆解他的任务筛选框架:**频次、明确性、容错性三个筛子**(一周做 3 次以上 / 输入输出可结构化 / 错一次不造成不可逆损失),以及一个典型反例(法务 AI 起草合同),并衔接站内其他落地方法论。

## 概念

- **核心论点**:Agent 落地失败,九成原因不在技术而在**筛选**。技术鸿沟(demo 到生产)是工程细节,别人已讲透;这里只讲**从项目视角能看到的问题**——筛错岗位、筛错任务、筛错组织土壤,掉进任何一个,Agent 都很难跑起来。
- **为什么重要**:它把"Agent 落地"从技术问题重新定义为**选型与组织问题**。同样的技术栈,选对了活儿能落地,选错了就是拿钱打水漂——而选错的原因往往在一开始就埋下。
- **与站内方法论的关系**:本文给出的是**事前筛选框架**("哪些活儿值得 Agent 化"),与站内 [企业 Agent 工程化(一):任务边界与工具治理](enterprise-agent-boundaries-tools.md) 的"六要素派工法"(事后控制任务边界)互补,共同回答"给 Agent 派什么活"。

## 原理:三个筛子

一个岗位或任务能不能交给 Agent,用三个筛子过一遍:

| 筛子 | 判断标准 | 反面教材 |
|---|---|---|
| **频次** | 一周做 **3 次以上**的重复动作才划算 | 低频活儿:调 prompt 的时间够人做十遍 |
| **明确性** | 输入输出**可以被结构化描述** | "整理客户反馈"不算;"从记录里抽投诉类别、产品、情绪等级"才算 |
| **容错性** | 错一次**不会造成不可逆损失** | 财报盖章、合同定稿不该是首个 Agent 化对象 |

- **三筛都过** → 这个活儿 Agent 能做。
- **三筛不过还硬做** → 拿钱打水漂。

### 典型反例:法务 AI 起草合同

某公司要求法务用 AI 起草所有合同。这个任务:**频次不高**(合同不是每天签)、**容错极低**(合同错一次后果不可逆)。结果是法务花更多时间去 review AI 输出,比自己写还慢——三个筛子里踩了两个,典型的"把不该给 Agent 的活儿交给了 Agent"。

## 代码 / 实现:筛选清单模板

实际推进 Agent 化时,把候选任务过一遍这张清单(可作为项目立项时的评审表):

```text
任务候选:____________________

1. 频次筛:过去 4 周做了多少次?
   - 每周 ≥ 3 次 → 过
   - 更低 → 停下:是否值得为它维护一套 Agent 配置?

2. 明确性筛:输入/输出能否写成结构化描述?
   - 输入:从 __ 提取 __(类别/实体/等级)
   - 输出:____(字段化的结果)
   - 写不出字段级描述 → 停下:先做 SOP,再谈自动化

3. 容错筛:错一次的最坏后果是什么?
   - 可逆、可重做、影响可控 → 过
   - 不可逆(盖章/定稿/付款/发公告)→ 标记为"仅辅助,人审签发"
```

## 实践 / 应用

- **选岗位优于选任务**:筛选的对象先是岗位再是任务——一个岗位如果 80% 的日常都是高频、结构化、低风险的重复动作,它就是 Agent 化的好起点。
- **首单避开高容错风险**:首批 Agent 化对象应从"错得起"的活儿开始,攒信任后再往高风险场景扩展——呼应站内 [企业业务 Agent 落地:四步渐进上线](enterprise-agent-business-rollout.md)(回放 → 影子 → 低风险放行 → 扩权)。
- **容错性不达标 ≠ 不能做**:财报盖章、合同定稿这类任务,不是永远不能 Agent 化,而是不该**首个** Agent 化——先让人做、Agent 做草稿/检查,验证稳定后再逐步放权。
- **组织土壤也是筛选对象**:原文提到"筛错组织土壤"是三大失败之一——Agent 落地同样需要组织准备度(数据是否干净、流程是否有 SOP、有没有人负责 review),可参考站内 [AI 原生组织方法论](ai-native-organization-methodology.md)。

## 总结

1. **Agent 落地失败,九成不在技术,在筛选**——筛错岗位、筛错任务、筛错组织土壤。
2. **三个筛子**:频次(一周 3 次+)、明确性(输入输出可结构化)、容错性(错一次不造成不可逆损失);三筛都过才值得 Agent 化。
3. **反例提醒**:法务 AI 起草合同——频次低 + 容错低,结果人比 AI 更忙。
4. **首单策略**:从高频、明确、低风险的活儿开始,渐进放权。
