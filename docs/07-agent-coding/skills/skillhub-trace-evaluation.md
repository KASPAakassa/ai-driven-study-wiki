# 腾讯 SkillHub:10 万+ Skill 的质量评测与分发——TRACE 五维体系 + 云端试运行 + find skill

> **一句话摘要**:当 Skill 从几百个增长到几万个,平台不能只是证明"这里什么都有",更要帮用户和 Agent **更快确认找到优质合适的 Skill**。腾讯 SkillHub(专为中国用户优化的 AI Skills 社区,10 万+ Skill、月下载 1000 万+)给出完整实践:TRACE 五维评测体系(Trust/Reliability/Adaptability/Convention/Effectiveness)+ 云端隔离试运行环境 + 榜单/标签组织供给 + **find skill(把发现能力开放给 AI)**。
>
> **来源**:微信公众号「腾讯程序员」《10万+Skill 背后:腾讯SkillHub如何帮用户找到真正好用的那20%》(赵秀雯),https://mp.weixin.qq.com/s/rSVXMwOMLSEhl7gC5KdBCg;官网 https://skillhub.cn;原始资料存档于 `docs/inbox/skillhub-trace-source.md`

## 概念:Skill 社区的内容治理难题

**二八法则**:真正有价值的内容往往只有 20%。AI 大大降低了创作成本——创作者用 AI 一句话生成一个 Skill 立刻发布(像五百年前抢注域名热潮),平台供给快速膨胀的同时,如何让用户找到那 20% 值得被看见的 Skill?

**三方关系**:

- **消费者**:希望更快找到可信、适合自己的 Skill;
- **创作者**:希望优质作品被公平看见、获得有效反馈;
- **平台**:在供给增长、分发效率和社区信任之间保持平衡。

**与普通社区的关键差异**:传统社区(豆瓣/知乎/App Store/小红书/淘宝)用**组织供给、分配流量、治理门槛、反馈闭环**四类成熟方法。但 Skill 的反馈有**滞后性**——真正使用是用户下载安装到 Agent 后才发生的,一个 Skill 被点击或下载,不代表它能成功完成任务。所以 SkillHub 必须补上普通社区很少深入处理的能力:**这个 Skill 到底好不好,依据是什么?**

!!! tip "类比"
    分类、榜单和行为数据仍然重要,但还不够。在讨论"如何推荐"之前,必须先建立质量坐标——SkillHub 的推荐工作本质是一套"**信任与分发基础设施**"。

## 原理:TRACE 五维评测体系——回答"什么是好的 Skill"

**出发点**:把"这个 Skill 好不好、是否值得信赖"从模糊感受变成可确认可解释的质量坐标。参考 Anthropic 的 Skill 规范标准 + 对用户痛点的洞察(渐进式披露没做好导致 token 消耗过大、自然语言 prompt 发散时 Skill 能否正确识别意图并处理好能力边界等)。

| 维度 | 评测子维度 | 主要回答的问题 |
| --- | --- | --- |
| **Trust(可信任度)** | 国内适配性、安全性扫描 | 元数据真实性、声明与实现一致性、来源可信度、安全边界(**放在首位**——海外 Skill 可能有内容合规性/安全风险/国内 API 不可调用问题) |
| **Reliability(可靠性)** | 异常处理、功能完整性、运行稳定性 | 依赖完整性、异常处理、重试机制、超时表现、实现缺陷 |
| **Adaptability(适用性)** | 能力边界定义、触发方式 | 参数兼容、异常路径、版本差异、环境容忍度、边界条件处理 |
| **Convention(规范性)** | 反模式与 FAQ、文档质量、渐进式披露、结构清晰 | 文档结构、参数 Schema、目录命名、依赖声明是否符合工程规范 |
| **Effectiveness(有效性)** | 输出准确性、内容完整度、创造力与增值、开箱即用度 | 产物是否正确、是否符合用户意图、Skill 能否真正完成任务 |

### 评测基础设施:三个关键设计

**1. 从单体串行到五路并行**:传统评测由单个 Agent 依次完成五维,每加一维就加等待时间。SkillHub 把 T/R/A/C/E 拆成五条并行链路——共享同一份 Skill 上下文,各自判断,统一做结构校验、冲突处理和结果汇总。**典型场景评测耗时从约 10 分钟缩短到约 1 分钟**,每维可独立扩容,新增规则无需推翻整套体系。

**2. 内存级加载**:五路评测各自解压读取文件(像五位检查员各拿一份复印件,慢且可能版本不一致)→ 将 Skill 包一次加载到内存,通过 `list_files`、`read_file` 等受控工具按需读取——减少重复操作、保证五维看到同一份内容、读取范围限制在当前 Skill 包内。

**3. 可追踪的"工单"**:一次模型调用能生成报告,但无法支撑持续运营。链路拆成"**发现—入队—调度—评测—审核—落库**",每个 Skill 有评测任务和状态,任何一步失败可记录、恢复、追踪——让 TRACE 从一次性 AI 判断变成**可长期运行的质量生产系统**。数万个 Skill 逐一扫描生成评测报告(用户侧简版 + 创作者后台详细版含优化建议)。

## 代码 / 实现:云端隔离试运行——测试 Skill 是否真能干

TRACE 静态分析只能证明 Skill"写了什么",不能证明"运行时会做什么"(安装脚本无法执行、文档声称支持但 Agent 不知如何调用、能生成结果但没真正解决问题)。SkillHub 因此搭建**云端隔离运行环境(封闭试车场)**:

**一次试运行的流程**:

1. 解析目标版本,把 Skill 文件装进**隔离 Workspace**;
2. Agent 读取 SKILL.md,按说明调用脚本、资料和工具;
3. **只有环境返回 ready 信号任务才开始**——排除"假运行"(模型知道 Skill 名字、生成像样回答但实际没加载使用它);
4. 文件读写/依赖安装/终端命令进独立工作区执行;平台业务服务与不可信代码彼此隔离;任务结束清理校验后才安全复用环境。

**执行轨迹与断点恢复**:把底层事件整理成用户能看懂的执行轨迹(做到哪一步/工具是否成功/正常完成还是中断);真实会话遇到网络中断、服务切换、环境重启时,保存消息、文件和关键运行状态,恢复时**必须确认 Workspace 和执行权限真的已恢复**(聊天记录还在 ≠ 运行环境还活着)。

**效果案例沉淀**:运行环境会话(实时、可继续、含完整上下文)与效果案例(从真实会话挑选的消息与文件快照)是两个不同对象——作者多轮对话后挑选最能说明效果的问答,生成 Skill 详情页可展示的案例。

**三个层面解决问题的证据链**:

| 层次 | 回答的问题 | 形成的证据 |
| --- | --- | --- |
| TRACE 测评 | 这个 Skill 看起来是否可信、规范、可理解 | 结构、依赖、说明、静态扫描结果 |
| 云端隔离运行环境 | 这个 Skill 在真实环境里能否被 Agent 正确使用 | 执行轨迹、工具调用、工作区变化、最终结果 |
| 效果案例 | 这次成功运行是否值得被其他用户看见和复用 | 经筛选、审核并持久化的真实会话快照 |

## 实践 / 应用:榜单、标签与 find skill

### 榜单:行为数据 + TRACE 维度融合

| 榜单 | 想解决的问题 |
| --- | --- |
| 推荐榜 | 找到近期质量和数据都相对稳定的 Skill |
| 飙升榜 | 捕捉时效性更强的新趋势 |
| 下载榜 | 保留最直观的长期热度入口 |
| 最新榜 | 给新品机会,同时过滤明显噪音 |

**设计细节**:长期霸榜的"装机必备"类 Skill 已在下载榜体现长期热度,推荐榜/飙升榜适度降权,为近期优质供给腾出空间;**人工运营始终存在**(新品冷启动、垂直内容捞取、热点专题承接、头部固化校准)——规则、算法和运营共同把海量供给压缩成用户可选择的有限集合。

### 标签:受控、分层的分类体系(克制优于放任)

- 12 个一级主分类(回答"我该去哪里逛");每个 Skill 归属 1 个一级分类 + 1-3 个二级类目(回答"它具体能做什么");行业类目(适合哪个行业);"需要 API Key"等系统标签(回答"我能不能直接用");
- **克制的原因**:对比某些社区让 AI 语义理解自动打标签——标签随意任意打,结果不但没提高筛选效率,反而增加理解成本;
- 存量 Skill 先系统自动打标,再逐步开放作者校正和后台治理;后续计划智能语言搜索。

### find skill:把发现能力开放给 AI

**核心命题**:Skill 面向的对象是谁?如果帮用户找 Skill 的不再是用户自己,而是 **Agent** 呢?(用户会在 Agent 中直接让 AI 推荐发现 Skill)

对比 skills.sh 的 find skill(先理解任务和领域→看热门榜单→CLI 关键词搜索→检查安装量/来源声誉/GitHub star→给候选与安装方式),SkillHub 面对中文自然语言需求与已建立的分类/评测/来源体系,封装了自己的 find skill:

1. 从用户原话**抽取任务意图、领域分类和中英文候选词**;
2. 对同义词、上位词做 **2-4 组扩展**(不只搜索一次原句);
3. 多次调用列表接口,必要时叠加一级分类和属性标签,合并后**按 slug 去重**;
4. 根据名称、中文描述和任务契合度重新排序,同一档位参考下载/安装热度;
5. **只保留最合适的 3-5 个结果,说明匹配理由**;用户确认后进入安装。

**示例**:“帮我自动写周报发给老板”不会只被当成关键词——Agent 先理解为"办公效率"场景,再扩展"周报、工作汇报、日报、weekly report"候选词;分类内结果太多就收窄,没有结果就去掉分类限制、换同义词和上位词放宽召回。**上线后无推广 3 天登飙升榜第一、一周破 8000 安装量**。

### 信任与分发基础设施的闭环

> 评测和试运行建立证据 → 榜单和标签组织供给 → 搜索与推荐分配注意力 → **find skill 把能力开放给 AI** → 最终的真实调用结果再回到评测和排序中。

## 总结

- **定位**:SkillHub 是专为中国用户优化的 AI Skills 社区(10 万+ Skill、月下载 1000 万+),解决"找到真正好用的那 20%"——本质是**信任与分发基础设施**;
- **TRACE 五维评测**:Trust(国内适配+安全,首位)/ Reliability / Adaptability / Convention / Effectiveness;基础设施三设计(五路并行 10min→1min、内存级加载、可追踪工单);
- **云端试运行**:隔离 Workspace + ready 信号防假运行 + 执行轨迹 + 断点恢复 + 效果案例沉淀(三层证据:静态/运行/案例);
- **分发**:榜单(推荐/飙升/下载/最新,行为+TRACE 融合)+ 受控分层标签(克制优于 AI 自动打标)+ find skill(中文意图抽取+同义词扩展+按 slug 去重+3-5 个推荐,开放给 AI);
- **与站内关系**:本篇是**平台级** Skill 质量治理,与 [Skill 测评](skill-evaluation.md)(个人五维测评框架)、[Skill 治理](skill-governance-registry.md)(团队 Registry 链路)互补——个人→团队→平台三层视角;
- **下一步**:对比站内 [Skill 测评](skill-evaluation.md)(两大核心/五大维度/测试闭环)理解不同层级的测评设计,或看 [Eval Engineering Skill](eval-engineering-skill.md)(评测自动化)。
