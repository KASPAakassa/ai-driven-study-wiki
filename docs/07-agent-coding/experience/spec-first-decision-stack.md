# Spec-First 决策栈:用 16 个思维模型校准 AI Coding 判断

> **一句话摘要**:大家都在卷模型、卷 prompt、卷 agent 数量,但真实工程里反复翻车的从来不是模型不够强,而是**判断没跟上**——该不该信这次输出、该不该让它继续改、这个改动到底动了多大范围。本文把 16 个经典思维模型压成四层决策栈(系统/本质/边界/长期)与一份 8 检查点清单,让"AI 该不该这么改"从直觉变成可逐层追问的链路。
>
> **来源**:微信公众号「leokuang」《Spec-First:我用 16 个思维模型,重新想清了 AI 工程怎么做》(番外篇),https://mp.weixin.qq.com/s/lqChZsjZAnqtSpAQd-XVhQ;原始资料存档于 `docs/inbox/spec-first-source.md`

## 概念:判断力是 AI coding 最缺的一层

两个工程师用同一个 AI、接同一个需求"给登录加个错误提示":
- 第一个人三句话甩过去,AI 改得飞快——半小时后开始救火:错误提示加上了,但顺手被改的认证逻辑挂了;
- 第二个人慢了五分钟:先问清是 bug fix 还是行为变更、圈定只动哪个文件、让 AI 给证据、跑测试,然后才合并,当晚就敢推上线。

!!! tip "差别不是 prompt 写得更好,是判断质量"
    第二个人赢在:**在 AI 动手之前,把这件事放进了一套可复用的思考框架里。** 该不该信这次输出、该不该让它继续改、这个改动到底动了多大范围——这些不是"写更长的 prompt"能解决的,它们是思考框架的问题;而思考框架,恰恰是人类已经积累了几十年的东西。

## 原理:四层决策栈

16 个模型按"每一组管一类问题"分成四层,对应决策栈的一层:**因果与系统看连锁、本质与概率看真假、边界与规律看深浅、长期与人性看远近**。

### 系统层:这件事会不会连锁放大?

| 模型 | AI coding 里对应的问题 | 落地动作 |
| --- | --- | --- |
| **蝴蝶效应** | 一个含糊的词("优化一下登录")会被多代理逐级放大成一次返工 | 需求澄清,把意图显式化;识别关键链路上的小问题,别过度解读无关 typo |
| **公地悲剧** | 共享上下文/memory/skill 池是公共资源,人人多塞,最后谁都判断被污染 | 给上下文划产权边界:默认不读易过期材料,引用最小片段而非整库投喂 |
| **复利效应** | 每次任务从零开始是最大的浪费 | 经验必须可沉淀、可被下次自动找到(写进 `docs/solutions/`,而非聊天记录) |
| **创造性破坏** | 新方法应替代低效惯性,不是装饰 | 替代"自由发挥然后人工救火",不替代人对产品/架构/风险的最终判断 |

### 本质层:底层事实是什么?这是概率还是确定?

| 模型 | AI coding 里对应的问题 | 落地动作 |
| --- | --- | --- |
| **第一性原理** | AI 最擅长"在旧方案上接着改"——初始方向若基于惯例假设,错误会被越描越细 | 先拆回行为契约、验证方式、状态真相源,再从底层推导;别把自己的假设误当第一性事实 |
| **奥卡姆剃刀** | 排查 bug 时 AI 爱给"并发竞争+连接池耗尽+缓存击穿"复合解释 | 先看简单原因:列假设、按概率排序、用证据逐个证伪;接口 500 往往只是上游改了个字段 |
| **概率思维** | 同一个 prompt 跑两次给两个答案——AI 输出是概率不是真相 | 关注期望收益,接受"好决策也可能翻车";结论必须带证据等级 |
| **回归均值** | 一次 demo 成功不代表系统稳定 | 先定义可度量目标与度量命令,跑多组实验;别用一次惊艳给系统定性 |

!!! warning "证据四等级(核心认知差)"
    **primary**(已确认:源码/测试/schema/命令结果支撑)/ **session-local**(仅本次会话)/ **advisory**(线索)/ **stale**(已过期)。同一句话"这个函数没有别的调用方",是 primary(真跑了引用查找)还是 advisory(扫了一眼)?证据等级不同,你承担的风险完全不同。**非法组合:能力 unavailable 却声称 primary 不允许**——堵的正是"工具没用上,却假装拿到了确认"。

### 边界层:我和 agent 到底懂不懂?

| 模型 | AI coding 里对应的问题 | 落地动作 |
| --- | --- | --- |
| **能力圈** | 通用 agent 不该什么都接 | 明确职责边界:"Scripts prepare, LLM decides"——脚本准备可复验事实,LLM 做语义判断;让脚本假装架构师=脆弱规则引擎,让 LLM 假装跑过校验=不可验证幻觉 |
| **帕累托法则** | 平均扫描所有可能 vs 聚焦高杠杆 | plan/review 聚焦 20% 关键风险点 |
| **边际效用递减** | "越多越好"到某个点变成协调成本 | 再拆任务/加文档/加 persona 前先问:新增收益还是治理变重? |
| **大数定律** | 用一两次"这招很灵"就定规则 | 判断哪 20% 关键要看足够多样本;几十次 review failure 指向同一缺口才值得固化 |

### 长期层:下一步、再下一步会怎样?

| 模型 | AI coding 里对应的问题 | 落地动作 |
| --- | --- | --- |
| **二阶思维** | 一阶收益带二阶损害:加了自动化规则,开发者会不会不再读 diff? | 推演后续激励;古德哈特定律——指标变成目标就不再是好指标,别把"生成代码行数"当目标 |
| **地图不是疆域** | spec 文档 ≠ 真实系统;AI 读文档、答得像在描述真实系统 | 关键结论落地前必须有源码/测试级证据回扣;文档只是上季度的地图,疆域早就变了 |
| **社会认同** | 好方法不是"我觉得对"就能被采用 | 用真实交付建立信任(scope 被锁住避免扩成重构、review 拦住不可验证结论) |
| **临界点效应** | 平台期投入没回报,最容易放弃 | 用指标区分"方向错了"和"还没到临界点":覆盖度在涨就值得走,停滞倒退才该转向 |

!!! tip "不要拿模型给已拍板的决定找理由"
    四层栈的用途是**提前暴露风险、校准边界、要求证据**,而不是事后把一次冲动包装成"系统思考"。

## 代码 / 实现:证据分级 + 非法组合校验(纯 Python)

把"证据四等级 + 非法组合拦截"落成可运行校验器(与 skill 篇同一逻辑的独立验证):

```python
VALID = {"primary", "session-local", "advisory", "stale"}

def check_claim(capability: str, level: str) -> dict:
    if level not in VALID:
        return {"verdict": "invalid", "reason": f"未知证据等级 {level}"}
    if level == "primary" and capability == "unavailable":
        return {"verdict": "blocked",
                "reason": "能力不可用却声称 primary(非法组合,疑似幻觉)"}
    return {"verdict": "ok"}

claims = [
    ("used",        "primary",  "跑过 grep,确认无调用方"),
    ("unavailable", "primary",  "扫了一眼,应该没调用方"),
    ("used",        "advisory", "provider 提示可能相关"),
]
for cap, lv, text in claims:
    r = check_claim(cap, lv)
    print(f"  [{r['verdict']:7}] {text} → {r.get('reason', '通过')}")
```

## 实践 / 应用:一份 AI coding 决策清单(8 检查点)

| # | 检查点 | 对应层/模型 |
| --- | --- | --- |
| 1 | 这件事最底层的事实是什么?是 bug fix 还是行为变更? | 本质/第一性原理 |
| 2 | 哪个小歧义会被放大?哪块共享上下文会被污染? | 系统/蝴蝶效应、公地悲剧 |
| 3 | 我和 agent 真的懂吗?哪 20% 是关键? | 边界/能力圈、帕累托 |
| 4 | 这个结论是 primary 还是 advisory?是趋势还是个例? | 本质/概率思维、回归均值 |
| 5 | 继续加任务、加文档,还有新增收益吗? | 边界/边际效用递减 |
| 6 | 这么做,然后呢?再然后呢? | 长期/二阶思维 |
| 7 | 我的计划被真实数据验证过吗? | 长期/地图不是疆域 |
| 8 | 这是临界点前的平台期,还是方向错了? | 长期/复利、临界点 |

**三句最值得内化的话**:
1. 不要只看结果,要看系统;
2. 不要只看当下,要看复利和二阶后果;
3. 不要迷信认知地图,要持续用现实校准。

## 总结

- **四层决策栈**:系统(连锁放大/公地)、本质(底层事实/概率)、边界(能力圈/关键少数)、长期(二阶后果/现实校准);
- **核心认知差**:AI 输出是概率不是真相——结论必须带证据等级,非法组合要拦截;
- **8 检查点**:动手前快速过一遍,把"AI 该不该这么改"从直觉变成链路;
- **落地形态**:模型不会替你做决定,但有了模型,每一次决定都发生在更好的判断条件里——spec-first 把这套判断从"靠个人经验"变成"项目里可复用的结构"(详见站内 [Spec-First Skill 收藏](../skills/spec-first-skill.md))。
