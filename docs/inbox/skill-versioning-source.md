## 视频要点(原文)
Skill 作为一种会改变 Agent 行为的可执行资产,其版本管理需分为**源代码和运行时两层**。
开发环境可跟随最新版,但**生产环境必须锁定明确版本**,并配合评测、兼容性检查和灰度验证,以确保新版本安全上线,同时保留快速回滚的能力。

### 源代码层:用 Git 管理
- 管理范围:版本控制的最小单位是**整个 Skill 目录**,而非单个文件。因为 Skill 的最终行为由说明、脚本、模板和参考资料共同决定。
- 变更流程:每次修改都需要有提交记录、评审人和变更说明。
- 依赖管理:脚本依赖的版本也需要锁定,避免因依赖升级而导致 Skill 行为意外改变。
- 版本标记:团队内部可使用**语义化版本**来标记业务发布——修复错别字等不影响兼容性的改动可升级修订号,而修改触发边界、删除步骤等不兼容改动则需升级主版本。
