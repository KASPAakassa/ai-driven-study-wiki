# 原始资料:Palantir案例丨通用磨坊5000万项决策背后的AI供应链

---

年省1400万美元，AI推荐70%被人工采纳，四年30亿美元战略的技术底座。这是一个"先建语义层、再让AI有脑"的工程实录。

一、决策规模：5000万项/年的运营现实
通用磨坊的供应链规模，足以让大多数企业的数字化转型团队重新审视自己的项目边界：
4000家供应商覆盖从农产品原料到包装材料的全链路

200+北美工厂每个工厂的产能、换线成本、人员配置各不相同

约120万客户订单/年每笔订单涉及物流路线、库存分配、产能排期

约5000万项运营决策/年由运营团队人工完成

100亿美元商品销售成本被这5000万项决策直接驱动

5000万项决策是什么概念？平均每天13.7万项，每小时5700项，每分钟近100项。这些决策不是"点按钮"，而是需要综合约束条件、产能上限、物流成本、交货窗口、库存水平等多维信息的判断。

任何一个决策的次优化，都会在100亿美元的成本基数上产生放大效应。百分之一的优化空间，就是1000万美元。通用磨坊和Palantir从2019年开始的合作，瞄准的就是这个空间。

二、第一阶段：不是上AI，是建本体论语义层
2019年合作启动时，通用磨坊做的第一件事不是训练模型，而是在Palantir Foundry的本体论上构建连接的数据基础。

200张表的语义化映射
团队整合了200张主数据和运营数据表，映射到本体论的对象和关系模型中。这里的"映射"是语义层面的重新定义：
对象类型定义将ERP中的"采购订单"、物流系统中的"运单"、生产系统中的"工单"等异构概念，统一映射为本体论中的标准对象类型，如"订单"、"工厂"、"供应商"、"运输路线"

关系类型定义建立对象之间的语义关联，如"订单-属于->客户"、"订单-经过->工厂"、"工厂-使用->运输路线"

属性映射统一不同系统中同一业务概念的属性定义，如ERP中的"交货日期"和物流系统中的"预计到达时间"映射为同一属性

多源数据对象类型与权限隔离
通用磨坊使用了Foundry的MDO（多源数据对象类型）能力。以"供应商"对象为例，其属性可能来自多个源系统：ERP有基本信息和合同条款，质量管理系统有质检评分，物流系统有交付记录。

MDO支持两种模式：
列级隔离：不同源系统的属性子集按权限隔离。质量团队的敏感属性（如质检评分）只对授权人员可见
行级隔离：同一对象类型的不同实例来自不同源系统。北美供应商和欧洲供应商的数据按区域权限隔离

这种设计是本体论的内生能力。在200张表映射完成后，通用磨坊拥有了单一真相源--所有后续AI能力都建立在这个语义基础之上。

三、精灵项目（ELF）：从数据系统到操作系统
数据基础建好后，通用磨坊基于Palantir AI平台构建了精灵项目（Project ELF，端到端物流流）--一个智能执行系统。传统数据仓库是"记录系统"，只能回答"发生了什么"；Palantir构建的是"行动系统"，能回答"应该做什么"并在人类审核之后执行。

技术架构
ELF的技术架构分为三层：
第一层：实时约束消费。 ELF实时消费三类约束数据：
约束条件交货窗口、客户要求、合同条款、法规限制

容量工厂产能、仓库容量、运输工具载重

网络成本不同物流路线的运输成本、换线成本、库存持有成本

这三类数据不是静态导入，而是通过Foundry的数据管道实时同步。当任何一项约束发生变化（如某条运输路线因天气中断），ELF能在下一次分析中立即反映。

第二层：批量分析与推荐生成。 ELF在夜间批处理中分析3000+订单的状态，自动检测两类机会：
中断风险某订单可能无法按时交货，需要调整路线或产能

成本优化某订单如果换一条物流路线或换一个工厂排产，可以降低成本

每检测到一个机会，ELF生成一条AI推荐，包含：推荐动作、预期效果、影响范围、风险提示。

第三层：人在回路审核与执行。 推荐推送到人工运营团队审核。团队可以：
接受推荐触发执行流程，自动下单、排产、调整路线

拒绝记录拒绝原因，反馈给AI模型用于持续优化

修改后接受调整推荐参数后执行

70%采纳率的背后
首席供应链官保罗·加拉格尔在2024年3月的Palantir用户大会上透露了一个关键信息：70%的采纳率是信任建设阶段的成果，未来目标是"take them off the loop"--让人工脱离审核回路，实现全自动执行。
从70%到全自动，需要三个条件：
标准化采纳指标：不是笼统的"采纳率"，而是按推荐类型、影响金额、风险等级分维度衡量

技能重塑：运营团队从"审核推荐"转向"训练AI"--标注数据、修正规则、设计边界

变革冠军：在每个业务部门培养内部推广者，让"用AI做决策"成为组织习惯

Foundry在这里提供了独特价值：实时展示已采纳和未采纳决策的机会成本。当运营团队看到"昨天拒绝的那条推荐，如果接受了会省多少钱"时，采纳率自然上升。

四、四年30亿美元战略：数据治理是底座
通用磨坊不是把Palantir当作一个独立的IT项目，而是作为四年30亿美元成本节省战略的技术底座。这30亿美元的构成：
供应链重构（HMM项目）：约20亿美元
全球转型：约10亿美元
数据治理重构

加拉格尔强调，30亿战略的前提是数据治理重构。通用磨坊将数据准确率提升到96-97%，覆盖三个层面：
主数据：供应商、客户、产品的统一定义
运营数据：订单、库存、产能的实时状态
交易数据：历史决策记录和结果

"单一真相源"不是一句口号，而是96-97%准确率支撑下的工程现实。没有这个准确率，AI推荐的采纳率不可能达到70%--业务人员不信任数据，就不会信任基于数据的推荐。

六、三条判断
判断一：先建语义层，还是先上AI？
通用磨坊的答案是明确的：先建语义层。200张表映射到本体论花了相当长时间，但这是后续所有AI能力的基础。没有96-97%的数据准确率和统一的语义定义，AI推荐不可能达到70%的采纳率。
如果你所在企业正在考虑"先上AI还是先治理数据"，通用磨坊的案例给出了答案：数据治理不是AI的前置条件，数据治理就是AI的一部分。

判断二：人在回路是过渡态还是终态？
70%的采纳率说明AI已经具备实用价值，但加拉格尔明确表示目标是"脱离人工回路"。这意味着人在回路是过渡态，不是终态。
但过渡态的时间长度取决于行业风险和监管要求。供应链领域可能3-5年实现自动化，但医疗、金融等领域可能需要更长时间。关键是在过渡期建立信任机制--让业务人员参与AI训练，让决策过程透明可审计。

判断三：数据平台是成本中心还是战略底座？
如果只看年省1400万美元，Palantir平台的投资回报率已经不错。但通用磨坊的真正赌注是四年30亿美元--数据平台是这30亿战略的技术底座。
这个判断的逻辑是：供应链优化的天花板不取决于算法有多好，而取决于数据有多准、语义有多统一、决策有多快。通用磨坊选择先把数据底座建好，然后在上面叠加一个个优化场景（物流、采购、生产），最终汇成30亿。
