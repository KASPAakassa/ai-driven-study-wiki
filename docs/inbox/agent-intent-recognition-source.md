Agent意图识别:面试题的满分回答

面试被问"Agent意图识别用小模型还是纯规则?",直接二选一就错了。这道题考察的不是技术偏好,而是工程化思维。正确答案是构建一个分层路由系统,根据场景的确定性、风险和成本,灵活组合规则、小模型和大模型,实现最优解。

一、面试题的陷阱:为何不能二选一?

面试官的问题看似是技术选型,实则考察你是否具备综合权衡的能力。直接站队任何一方,都表明你只看到了局部,而忽略了工程落地的复杂性。

技术方案 优点 缺点
纯规则 速度快、结果稳定、可解释性强 无法处理同义表达、规则膨胀后难以维护、容易漏判
纯小模型 能理解上下文和同义表达 需要样本、训练和持续维护、对边界明确的场景是"大炮打蚊子"

二、正确思路:构建分层路由漏斗

真正的工程落地,是将不同技术组合成一个从确定到开放、从快到慢的处理漏斗,各司其职。

规则层 (高确定、强约束):处理边界明确、风险高的意图,如固定命令、合规拦截。
小模型层 (表达多样、请求量大):处理意图集合固定但表达方式多样的高频请求,如客服路由。
大模型/人工层 (长尾、模糊请求):处理低置信度、超出已知范围的请求,作为兜底。

三、各层技术的适用场景与考量

规则层:处理高确定性场景
规则是处理硬边界的最佳选择,它快、稳、可解释。
✅ 适用场景:查余额、重置密码、删除账号、敏感词拦截等有明确关键词和硬约束的操作。
⚠️ 注意事项:规则应保持精简,只保留高价值、低歧义的场景。过多的规则会变得难以维护,形成"规则毛球"。

小模型层:处理高频多样请求
当意图集合相对固定且已积累足够样本时,小模型能高效处理大量同义异构的请求。
✅ 适用场景:客服系统的第一跳路由,将几十到几百种同义说法归类到固定意图。
⚠️ 注意事项:需关注线上真实表现,如分意图准确率、低置信覆盖率、误触发高风险动作的比例,以及数据漂移问题。

大模型/人工层:兜底处理模糊请求
对于规则和小模型都无法处理的低置信度、长尾或高度开放的问题,需要更强大的能力来兜底。
✅ 适用场景:小模型低置信度输出、发现超出已知意图范围的请求、需要深度理解的复杂问题。
⚠️ 注意事项:这是成本最高的一层,应尽量减少其调用量。对于退款、删数据等高风险动作,宁愿多一次澄清,也不能错误执行。

四、满分回答框架

1. 破题表态:明确指出不会二选一,因为它们优化的是不同目标,应组合使用。
2. 分层阐述:分别说明规则、小模型、大模型的定位和优势。
3. 工程算账:强调评估标准不应只有准确率,而应是多维度的综合考量。

评估维度 核心关注点
准确率 分意图的线上准确率、低置信覆盖率
性能成本 P95延迟、单请求成本
业务指标 人工介入率、误执行率(尤其是高风险动作)
可维护性 规则维护成本、模型迭代成本

五、一句话带走

Agent意图识别的精髓在于分层协作,而非技术站队。用规则守边界,用小模型提效率,用大模型兜底。最终目标是在保证准确性、稳定性和成本可控的前提下,为用户提供流畅的服务。
