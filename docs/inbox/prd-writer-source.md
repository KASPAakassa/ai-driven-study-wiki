很多产品经理用 AI 写需求文档，结果往往是：方向没对齐就堆细节，写完才发现走不通；或者文档很长，研发和设计仍反复追问。prd-writer 把产品经理的核心工作流封装成可执行技能——先对齐方向，再写落地细节，自带评审与增量更新。

CHAPTER 01

01它是什么？PARAGRAPH TITLE

prd-writer 是专为产品经理、创业者及技术负责人设计的AI PRD写作助手，也是 VibePM 工作流里的「PRD 撰写与迭代」技能，适用于：从零写 PRD、评审已有需求稿、在现有 PRD 里追加模块而不改乱原文。它瞄准传统 PRD 撰写中耗时费力、结构易遗漏、细节难把控的痛点，并不替代人的思考，而是作为「副驾驶」——通过引导式交互和结构化扩展，将模糊想法快速转化为逻辑严密、格式规范的高质量 PRD 草案，显著提升文档产出效率与一致性。核心理念是把 PM 的分阶段思维变成 AI 必须遵守的门禁——不是一次性输出长文，而是按步骤交付、逐步确认：先验证方向 → 概念版对齐 → 落地版展开 → 写后自检。

下面是一份完整实战示例：以「生鲜超市 App」为题材，从三视角诊断到概念版确认，再到落地版展开 MVP 功能、交互状态与线框图——你可以直观看到 prd-writer 最终能产出什么样的文档。

CHAPTER 02

02适合谁？不适合谁？PARAGRAPH TITLE

不适合：完全没方向、希望 AI 代为选题或想商业模式的场景——它会先问「你想解决什么问题，大概想用什么方式解决？」，答不上来就引导你先想清楚，而不是硬写空 PRD。

CHAPTER 03

03三种工作模式PARAGRAPH TITLE

交付节奏（可选声明）：未特别声明时默认为 标准模式——概念版对齐方向后写落地 PRD；说「快速模式」或「直接写 PRD / 跳过概念版」则合并为单文件；说「严格模式」或「正式交付」则须概念版明确确认后再写落地 §5。

CHAPTER 04

04五个核心能力PARAGRAPH TITLE

1. 三视角诊断 — 动笔前对齐用户（痛点真实吗）、商业（值得做吗）、技术（做得出来吗），并推荐产品形态（Web/小程序/App）及理由。

2. 分两版交付 — 标准模式（默认）下概念版只对齐方向，不展开实现细节；落地版含动线、§5、状态机、文案、线框图。严格模式下概念版未明确确认，不写落地细节（「差不多」不算确认）。说「快速模式」可合并为单文件，方向摘要写在文首。

3. MVP 闸门 — 落地版默认只展开 🔴 核心功能的 §5；🟡⚪ 仅在清单留名。以《生鲜超市APP》为例：7 个 🔴 模块写全（首页至订单），领券/邀请仅列项，鲜友圈标「不做」。

4. 补全盲区 — 交互反馈、空状态、状态机、数据校验、双受众文案（开发规格 vs 用户文案）、关键页线框图，以及按产品类型补充非功能需求。

5. 先读再写 — @ 已有文档或 docs/ 里的 PRD/调研稿会先读、摘录真源，只补缺口，不从零重写。

CHAPTER 07

07怎么使用技能PARAGRAPH TITLE

提到「PRD」「写需求」「审查需求」「我想做个 App」等词，Agent 会自动加载本技能；也可手动指定 SKILL.md。

模式 A · 从零写

我想做一个城市家庭用的生鲜即时零售 App，强调鲜活品质承诺和极速达配送，请按 prd-writer 流程帮我写 PRD。

Agent 三视角诊断后输出概念版（对齐定位与「不做什么」），你确认后再写落地版——含动线、交互状态表、线框图与字段规范。

模式 B · 评审

帮我检查一下这份生鲜超市 App 需求文档有没有问题 @docs/2026-06-25-生鲜超市APP-PRD.md

按清单评审动线、状态与验收标准，产出 PRD-评审.md，再问你直接补全还是自行修改。

模式 C · 增量

帮我在现有生鲜超市 PRD 里补充「黄金会员」权益与升级规则 @docs/2026-06-25-生鲜超市APP-PRD.md

定位相关章节融合更新，用 【本次更新】 标注，不覆盖原文。

CHAPTER 08

08工作流与技能衔接PARAGRAPH TITLE

prd-writer 门禁：读稿 → 模式 A/B/C → 三视角诊断 → 概念对齐（或概念版确认）→ 落地版（MVP 闸门）→ 自检。

prd-writer 是 VibePM 工作流 「文档 → 结构 → 原型 → 测试/手册」 链中的需求中枢，产出在 docs/，下游读取上一阶段文件衔接。

CHAPTER 09

09写在最后PARAGRAPH TITLE

AI 写 PRD 的最大坑不是写不出来，而是写得太快、太满、方向未对齐细节已固化。prd-writer 把「先对齐再展开、三视角过一遍、MVP 优先、补盲区、增量不覆盖」固化成门禁。不妨从一句开始：

「我想做一个生鲜即时零售 App，主打极速达和鲜活品质承诺，请按 prd-writer 帮我写 PRD。」
