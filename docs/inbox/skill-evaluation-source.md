# 原始资料:如何证明 Skill 的有效性——Skill 测评(视频)

## 核心内容(原文)
Skill 的核心事故并非不会执行,而是**乱触发或抢任务**。测评需从多维度进行:触发准确性、独立执行、共存冲突、指令遵循、最终输出质量。

### 两个核心方面
- 测触发:评估 Skill 是否能被正确触发,避免误触发或漏触发
- 测执行:检查 Skill 执行时是否遵循正确流程和逻辑,确保执行无误

### 五大维度
1. 触发准确性:不同输入下的触发情况,确保触发行为符合预期
2. 独立执行:无其他技能干扰下,是否能独立完成任务
3. 共存冲突:多个 Skill 共存时,是否抢任务或执行冲突
4. 指令遵循:是否严格遵循用户指令,包括参数传递和执行顺序
5. 输出质量:最终结果是否正确、完整

### 各维度测试方法与成功标准
- 触发测试:提供至少三类输入(正常/边界/错误),观察是否按预期触发 → 无漏触发或误触发
- 执行测试:检查是否读取正确文件/调用正确 API → 执行流程正确无逻辑错误
- 共存测试:模拟多 Skill 同时存在场景 → 各 Skill 协同工作无任务冲突
- 指令测试:验证是否严格遵循指令(参数和执行顺序) → 完全遵循无自主行为
- 输出测试:检查最终结果正确完整 → 无信息缺失

### 测试闭环与持续监控
- 建立基线:上线前通过测试建立性能和行为的初始基线
- 线上监控:持续监控触发准确率、执行成功率、冲突发生率等关键指标
- 回流优化:根据监控发现的问题(触发准确率下降/冲突增多)及时迭代优化并重新测试,形成完善闭环
