# 原始资料:AI时代的代码审查:Agentic Code Review

> 来源:用户提供(方法论文案,引用谷歌技术总监观点);抓取日期:2026-08-09
> 状态:已整理为正式文章 docs/07-agent-coding/experience/agentic-code-review.md

## 核心内容(原文)
AI 大幅提升代码产出,但真实交付价值增长有限,瓶颈在代码审查。人从"逐行阅读"的内环退出,成为"信号决策者":分层审查、多 AI 交叉验证、建立新规则。

一、问题:产出 4 倍 vs 交付价值仅 +12%;难点从"写代码"变"决定是否信任代码"。

二、分层审查策略:按风险三变量(爆炸半径/代码寿命/受众广度)定档——低风险(UI 微调)=Linter+人工快览;中风险(常规业务)=测试+AI 审查+人工确认;高风险(支付/鉴权)=全流程:类型检查+测试+多 AI 交叉审+系统 Owner+安全审计。

三、异质性 AI 传感器阵列:不同"性格"的 AI 审查工具发现问题重叠率极低 → 部署功能各异的 AI 传感器交叉验证;人不再是传感器,而是站在阵列后综合信号做最终决策。

四、Agent 提交规则(入口契约,把理解成本推回提交者):
- 提交决策日志(Decision Log):Agent 附推理过程(为什么这么改/排除了哪些方案),避免 Reviewer 从零"考古"
- 强制小 PR:大 PR 要么拒要么草率通过;PR 大小作为硬性设计约束
- 提交必须附带证据:变更目的、测试输出等,否则不配进审查流程

五、人类新角色:四大关键任务
- 判断 PR 是否值得审(识别 Agent 易放弃的任务,不在注定失败的 PR 上浪费时间)
- 重点审查测试改动(警惕 Agent 为通过测试而"修复"测试——最隐蔽失败模式)
- 高风险 PR 深度审查(核心系统改动亲自深入,不依赖 AI)
- 承担最终责任(谁按 Merge 谁负责)

六、一句话:AI 时代代码审查 = 人主导、AI 辅助的决策系统;分层策略+多 AI 交叉验证+严格提交规则,把人的精力从机械阅读解放到高价值决策。
