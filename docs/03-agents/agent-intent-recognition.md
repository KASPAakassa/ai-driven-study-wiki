# Agent 意图识别:分层路由系统——规则守边界、小模型提效率、大模型兜底

> **一句话摘要**:面试被问"Agent 意图识别用小模型还是纯规则?",直接二选一就错了——考察的不是技术偏好,而是工程化思维。正确答案是构建**分层路由系统**:根据场景的确定性、风险和成本,组合**规则层(高确定、强约束)→ 小模型层(表达多样、高频)→ 大模型/人工层(长尾、模糊兜底)**,形成从确定到开放、从快到慢的处理漏斗。本文给出完整框架、各层适用场景与评估维度。
>
> **来源**:用户提供的面试题拆解(素材存档于 `docs/inbox/agent-intent-recognition-source.md`)

## 概念:为何不能二选一

**面试题陷阱**:看似是技术选型,实则考察综合权衡能力。直接站队任何一方,都表明只看到局部、忽略工程落地的复杂性。

| 技术方案 | 优点 | 缺点 |
| --- | --- | --- |
| 纯规则 | 速度快、结果稳定、可解释性强 | 无法处理同义表达、规则膨胀后难以维护、容易漏判 |
| 纯小模型 | 能理解上下文和同义表达 | 需要样本、训练和持续维护;对边界明确的场景是"大炮打蚊子" |

> **核心认知**:规则和小模型优化的是**不同目标**——规则追求"快、稳、可解释",小模型追求"能理解表达多样性"。它们是互补关系,应组合使用,而非二选一。

## 原理:分层路由漏斗

真正的工程落地,是把不同技术组合成一个**从确定到开放、从快到慢的处理漏斗**,各司其职:

```
请求
 ├─ 规则层    (高确定、强约束)   → 边界明确、风险高的意图(固定命令、合规拦截)
 ├─ 小模型层  (表达多样、请求量大) → 意图集合固定但表达多样的高频请求(客服路由)
 └─ 大模型/人工层(长尾、模糊请求)  → 低置信度、超出已知范围,兜底
```

**每层只处理自己擅长的问题,不越级**——规则的漏判交给小模型,小模型的低置信度交给大模型,大模型的高风险动作再交给人工确认。

## 代码 / 实现:各层适用场景与考量

### 规则层:处理高确定性场景

规则是处理**硬边界**的最佳选择——快、稳、可解释。

- **✅ 适用**:查余额、重置密码、删除账号、敏感词拦截等有明确关键词和硬约束的操作;
- **⚠️ 注意**:规则应**保持精简**,只保留高价值、低歧义的场景——过多规则会难以维护,形成"规则毛球"。

### 小模型层:处理高频多样请求

当**意图集合相对固定且已积累足够样本**时,小模型能高效处理大量同义异构请求。

- **✅ 适用**:客服系统的第一跳路由,把几十到几百种同义说法归类到固定意图;
- **⚠️ 注意**:需关注线上真实表现——分意图准确率、低置信覆盖率、误触发高风险动作比例,以及**数据漂移**问题。

### 大模型/人工层:兜底处理模糊请求

对规则和小模型都无法处理的低置信度、长尾或高度开放问题,需要更强能力兜底。

- **✅ 适用**:小模型低置信度输出、超出已知意图范围的请求、需要深度理解的复杂问题;
- **⚠️ 注意**:这是**成本最高**的一层,应尽量减少调用量;**对退款、删数据等高风险动作,宁愿多一次澄清,也不能错误执行**。

```python
# 分层路由概念示意
def route_intent(request):
    # 1. 规则层:高确定、强约束(查余额/重置密码/敏感词)
    if rule_matcher.is_hard_boundary(request):
        return rule_matcher.handle(request)          # 快、稳、可解释

    # 2. 小模型层:高频多样(客服路由,固定意图集合)
    intent, confidence = small_model.classify(request)
    if confidence >= SMALL_MODEL_THRESHOLD and not high_risk(intent):
        return small_model.handle(intent)            # 高效处理同义异构

    # 3. 大模型/人工层:低置信、长尾、高风险
    if high_risk(intent):                             # 退款/删数据:宁可多澄清
        return human_clarify(request)
    return large_model.handle(request)                # 深度理解兜底
```

## 实践 / 应用:满分回答框架与评估

### 满分回答四步

1. **破题表态**:明确指出不会二选一——它们优化不同目标,应组合使用;
2. **分层阐述**:分别说明规则(守边界)、小模型(提效率)、大模型(兜底)的定位与优势;
3. **工程算账**:评估标准不只是准确率,而是多维综合考量;
4. **收尾点睛**:意图识别的精髓是分层协作,而非技术站队。

### 评估维度(工程算账)

| 评估维度 | 核心关注点 |
| --- | --- |
| 准确率 | 分意图的线上准确率、低置信覆盖率 |
| 性能成本 | P95 延迟、单请求成本 |
| 业务指标 | 人工介入率、误执行率(尤其是高风险动作) |
| 可维护性 | 规则维护成本、模型迭代成本 |

## 总结

- **不要二选一**:规则和小模型优化不同目标——规则求"快稳可解释",小模型求"懂表达多样",应组合使用;
- **分层漏斗**:规则层(高确定强约束)→ 小模型层(高频多样)→ 大模型/人工层(长尾模糊兜底),从确定到开放、从快到慢;
- **每层注意**:规则保持精简防"规则毛球";小模型盯线上指标与数据漂移;大模型成本最高、高风险动作宁可多澄清不误执行;
- **评估多维**:准确率(分意图/低置信覆盖率)+ 性能成本(P95/单请求)+ 业务指标(人工介入/误执行)+ 可维护性;
